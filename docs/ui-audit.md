# ممیزی UX و رابط کاربری cara — فاز A

> وضعیت: ممیزی ایستا از سورس شاخه `main`، تاریخ ۲۰۲۶-۱۱-۰۸  
> محدوده: فقط مشاهده و مستندسازی؛ هیچ تغییر اجرایی/کدی در این فاز مجاز نیست.  
> محدودیت اعتبارسنجی: اسکرین‌شات‌های واقعی و آزمون تعاملی مرورگر در این نوبت قابل تهیه نبودند. دسترسی شبکه‌ی محیط اجرای محلی به GitHub و `caraw.ir` برقرار نشد؛ بنابراین clone محلی ناموفق بود و Chromium نتوانست سایت زنده را بارگذاری کند. موارد زیر یافته‌های قطعی از HTML/CSS/README هستند، نه ادعای مشاهده‌ی پیکسل‌های سایت.

## 1) وضعیت شواهد و پوشش

- سورس از GitHub خوانده شد؛ README، `css/README.md`، صفحات اصلی، CSSهای مشترک، فونت‌ها، تست‌های موجود و `js/palette.js` بررسی شدند.
- اجرای Chromium headless روی `https://caraw.ir/` به علت عدم دسترسی شبکه به تصویر منجر نشد؛ clone مخزن نیز با خطای DNS شکست خورد.
- در نتیجه **هیچ اسکرین‌شات واقعی 375/768/1280 ثبت نشده** و هیچ صفحه‌ای از نظر بصری «تأییدشده» محسوب نمی‌شود.
- ماتریس تصویربرداری لازم: هر صفحه در عرض‌های 375px، 768px و 1280px، با ارتفاع viewport ثابت و اسکرول کامل صفحه؛ ثبت حالت منو بسته/باز، حالت خطا/خالی/موفق و فرم‌های تعاملی.
- تعداد ۱۷ صفحه‌ی کار/نمونه‌ی دستبند در مسیر `bracelet/` وجود دارد. صفحات رنگ در `colors/` نیز جداگانه در درخت مخزن موجودند.

## 2) یافته‌های سراسری

### اولویت بحرانی / بالا

1. **منوی موبایل به چند لایه‌ی CSS وابسته است.** `css/mobile-nav.css` به‌تنهایی عرض 188px، ارتفاع لمس 35px و متن 13px تعریف می‌کند؛ سپس `polish.css?v=1` با قواعدی دیگر آن را override می‌کند. این وابستگی به ترتیب لود، نگهداری و یکسانی تجربه را شکننده می‌کند. ارتفاع دکمه‌ی منو 38px است و به حداقل 44px نمی‌رسد. لینک‌های منو در لایه‌ی اولیه 35px هستند؛ باید اندازه‌ی مؤثر نهایی در مرورگر اندازه‌گیری شود.
2. **سند ترتیب CSS با واقعیت صفحات هم‌خوان نیست.** `css/README.md` ترتیب کوتاه و قدیمی‌تری را شرح می‌دهد، درحالی‌که صفحات فعلی فایل‌های `fonts.css`، `accessibility.css`، `mobile-nav.css` و `polish.css?v=1` را با ترتیب‌های متفاوت اضافه می‌کنند. نمونه: صفحه‌ی اصلی چندین CSS اختصاصی را پیش از accessibility/mobile-nav/polish می‌خواند؛ builder نیز builder.css را قبل از این لایه‌ها می‌خواند. قبل از فاز C باید نقشه‌ی واقعی و ترتیب نهایی به‌صورت دقیق مستند شود.
3. **استفاده از style درون HTML با محدودیت CSP کاربر ناسازگار است.** در سورس فعلی: صفحه‌ی اصلی ۲ بلوک `<style>`، builder یک بلوک، upload یک بلوک، gallery یک بلوک، admin دو بلوک و customers یک بلوک دارند. همچنین attributeهای `style=""` در چند صفحه دیده می‌شود. در فاز A فقط ثبت شده؛ انتقال آن‌ها به CSS خارجی باید در فاز پیاده‌سازی برنامه‌ریزی شود.
4. **مقیاس تایپوگرافی موبایل یکدست نیست.** در `css/mobile-nav.css` متن لینک منو 13px و حداقل ارتفاع لینک 35px است؛ در `css/polish.css` کارت‌های گالری در breakpoint کوچک عنوان 13px دارند. این با معیار «هیچ متن زیر 16px در موبایل» تعارض دارد. موارد دیگر باید با محاسبه‌ی computed style در مرورگر بررسی شوند.
5. **محدودیت بودجه‌ی فونت رعایت نشده است.** `fonts/` شامل ۱۵ فایل woff2 برای Vazirmatn (۵ وزن × ۳ زیرمجموعه‌ی Arabic/Latin-ext/Latin) است؛ هر فایل در درخت مخزن حدود 21–46KB ثبت شده. CSS نیز وزن‌های 300/400/500/700/900 را تعریف می‌کند. هرچند فونت‌ها self-host و دارای `font-display: swap` هستند، سقف «حداکثر ۴ فایل» فعلی رعایت نمی‌شود. preload موجود در index به فایل عربی 400 اشاره می‌کند؛ preloadهای صفحات دیگر باید بررسی شوند.
6. **404 اختصاصی در ریشه‌ی مخزن پیدا نشد.** درخت فعلی شامل `offline.html` است، اما `404.html` وجود ندارد. باید رفتار واقعی GitHub Pages و مقصد مسیرهای نامعتبر در مرورگر ثبت شود.
7. **صفحه‌ی مستقل weave وجود ندارد.** فایل‌های `weave.css` و `weaving.css` در صفحه‌ی اصلی لود می‌شوند؛ بنابراین «weave» فعلاً بخش/تجربه‌ای از صفحه‌ی اصلی است، نه HTML مستقل. باید همان بخش در ممیزی home به‌عنوان زیربخش جداگانه بررسی شود.

- اندازه‌ی واقعی hit area، فوکوس کیبورد، ترتیب tab، نام accessible کنترل‌ها و نسبت کنتراست متن روی عکس/گرادیان بدون اجرای مرورگر قابل تأیید نیست.
- جهت کلی صفحات HTML فارسی `lang="fa" dir="rtl"` است. صحت جزئی ZWNJ، اعداد فارسی، قیمت‌ها و ورودی‌های عددی باید در متن‌ها و فرم‌ها صفحه‌به‌صفحه بازبینی شود.

### چیزهایی که در سورس فعلی خوب هستند و باید حفظ شوند

- مرجع رنگ‌های فیزیکی منجوق‌ها در `js/palette.js` متمرکز است؛ ۳۳ رنگ در آرایه‌ی `CARA_PALETTE` تعریف شده‌اند و `drawBead/drawPattern` از hex همان منبع برای رسم استفاده می‌کنند. این رنگ‌ها نباید با توکن‌های UI جایگزین شوند.
- فونت Vazirmatn به‌صورت محلی میزبانی می‌شود و `font-display: swap` دارد؛ هیچ وابستگی ضروری به CDN فونت در CSS بررسی‌شده دیده نشد.
- لایه‌ی CSS دسترس‌پذیری لینک پرش و focus-visible را فراهم کرده و در صفحات اصلی به کار رفته است.
- احترام به `prefers-reduced-motion` در لایه‌ی مشترک وجود دارد و باید در بازطراحی حفظ و کامل شود.
- برای طراحی دستبند و تبدیل عکس، canvas واقعی و ابزارهای اختصاصی وجود دارد؛ این ابزارها و دقت رنگ beadها دارایی اصلی محصول‌اند و نباید قربانی تزئینات UI شوند.
- صفحات نمونه‌ی دستبند و رنگ‌ها از صفحات HTML تولیدشده استفاده می‌کنند؛ قرارداد تولید صفحات و لینک‌های داخلی باید حفظ شود.
- صفحه‌ی آفلاین و PWA در مخزن وجود دارند؛ تجربه‌ی offline باید در بازطراحی از بین نرود.
- صفحه‌ی checkout و جریان سفارش از صفحات مستقل هستند؛ ممیزی/بازطراحی بعدی باید فقط ظاهری باشد و منطق سفارش، قیمت و پرداخت دست‌نخورده بماند.

## 5) چک‌لیست تعامل و شواهد لازم در دور مرورگر

- [ ] منوی موبایل در تمام صفحات: باز/بسته با لمس و کیبورد، خارج از منو click، Escape، focus trap فقط در صورت modal بودن، عدم پوشاندن CTA/محتوا.
- [ ] همه‌ی کنترل‌ها: hit target حداقل 44×44px، focus-visible با کنتراست حداقل 3:1، ترتیب tab منطقی.
- [ ] تمام متن‌های موبایل: حداقل 16px، به‌جز استثناهای ضروری که باید با دلیل ثبت شوند.
- [ ] عرض سند از viewport بیشتر نباشد؛ در 375/768px هیچ horizontal scroll یا overlap وجود نداشته باشد.
- [ ] فرم‌ها: label واقعی، خطا کنار فیلد، aria-live، حفظ مقدار پس از خطا، حالت loading/disabled/success/error.
- [ ] builder: لمس swatchها، undo/redo، zoom/pan، scroll صفحه، save/load، انتخاب رنگ و دقت hex.
- [ ] upload: انتخاب فایل، خطای نوع/حجم، crop touch، پردازش طولانی، لغو و retry.
- [ ] checkout: فقط visual UX؛ بدون تغییر JS یا API پرداخت/سفارش/قیمت.
- [ ] تصاویر/ویدئو: ابعاد ثابت برای جلوگیری از CLS، lazy-load غیر LCP، poster سبک برای ویدئوی خانه.
- [ ] Lighthouse Mobile قبل از هر PR پیاده‌سازی: Performance، Accessibility، Best Practices، SEO؛ اکنون baseline قابل اندازه‌گیری نیست و نباید عددی حدس زده شود.

## 6) وضعیت فاز A و گام لازم برای تکمیل

این فایل یک **ممیزی اولیه‌ی سورس** است، نه تأیید بصری نهایی. برای تکمیل بخش الزامی اسکرین‌شات‌ها و اندازه‌گیری‌های واقعی لازم است اجرای مرورگر به سایت زنده یا یک clone کامل با assetها و وابستگی‌ها دسترسی داشته باشد. پس از فراهم شدن آن دسترسی، باید تصاویر و یافته‌های مشاهده‌ای به همین سند اضافه شوند. تا آن زمان هیچ مسیر طراحی انتخاب یا پیاده‌سازی نمی‌شود.

### فونت‌ها و مجوز

- فقط خانواده‌ی Vazirmatn در CSS فونت فعلی تعریف شده است.
- ۱۵ فایل woff2 موجودند: سه subset (Arabic، Latin، Latin-ext) × پنج وزن (300، 400، 500، 700، 900).
- مجموع حجم فایل‌ها بر اساس metadata درخت GitHub: **513,460 bytes (~501 KiB)**؛ این مجموع همه‌ی فایل‌هاست، نه حجم دانلود هر صفحه. مرورگر subsetهای لازم را بر اساس unicode-range درخواست می‌کند.
- `font-display: swap` تعریف شده است. Preload و subsetهای واقعی باید با Network panel در مرورگر سنجیده شوند؛ فقط یک preload بحرانی باید نگه داشته شود.
- فایل مجوز OFL یا متن مجوز فونت در درخت مخزن پیدا نشد. بنابراین در این ممیزی نمی‌توان مجوز فایل‌های باینری موجود را از داخل مخزن تأیید کرد. پیش از پیشنهاد/بسته‌بندی فونت در فاز B، منبع رسمی upstream و فایل SIL Open Font License باید جداگانه بررسی و همراه assetها نگهداری شوند.
- اسکریپت `tools/self-host-fonts.js` و تست `test/self-host-fonts.test.js` در مخزن وجود دارند؛ پیش از تغییر تعداد فایل‌ها باید بررسی شوند تا build خودکار فونت، unicode-range، preload و تست‌ها با معماری جدید سازگار بمانند.
